## Request/Response Flow Detail

### Phase 1: Download Global Model
```
CLIENT                              SERVER
│                                   │
├──GET /get_model ────────────────►│
│                                   │
│  • Returns current model weights  │
│  • Returns current round number   │
│                                   │
│◄──JSON Response Module{────────────┤
│   {                                │
│     "weights": [v1, v2, ...],     │
│     "bias": b,                    │
│     "round": 1                    │
│   }                               │
│                                   │
```

### Phase 2: Local Training
```
CLIENT                   (no server communication)
│
├─── LOAD DATA: X_train, y_train
├─── LOAD WEIGHTS: from server
├─── TRAIN: model.fit(X_train, y_train)
│   ╔══════════════════════════════╗
│   ║ Training (1-100ms on CPU)    ║
│   ║ Calculate new weights        ║
│   ╚══════════════════════════════╝
├─── EXTRACT: weights, bias
│    Ready to send back
```

### Phase 3: Upload Updates
```
CLIENT                              SERVER
│                                   │
├──POST /update_model ─────────────►│
│  {                                │
│    "client_id": "client_1",      │
│    "weights": [w1, w2, ...],     │
│    "bias": b,                    │
│    "num_samples": 100            │
│  }                               │
│                                   │ STORE IN MEMORY:
│                                   │ {
│◄──JSON Response Module─────────────│   "client_1": {
│   {                                │     "weights": [...],
│    "success": true,              │     "bias": b,
│    "message": "Update received",  │     "num_samples": 100
│    "round": 1                    │   }
│   }                               │ }
│                                   │
```

### Phase 4: Server Aggregation
```
SERVER                              PROCESS
│                                   │
├─ Updates received from:           │
│  • client_1: weights_A            │
│  • client_2: weights_B            │
│  • client_3: weights_C            │
│                                   │
├─ Calculate average:               ├─ Simple Average:
│  (A + B + C) / 3                 │   weights = (A + B + C) / 3
│                                   │   OR
│  OR                              ├─ Weighted Average:
│  (A*n1 + B*n2 + C*n3)/(n1+n2+n3) │   w = (A*100 + B*120 + C*80) / 300
│                                   │
│  Update global model              │
│  global_round += 1                │
│                                   │
│  Clear updates for next round     │
```

## Federated vs Centralized Comparison

```
╔═══════════════════════════════════════════════════════════════╗
║                   CENTRALIZED LEARNING                        ║
╚═══════════════════════════════════════════════════════════════╝

Data                Server              Model
├─ D1            ├─ D1+D2+D3 ────► ├─ Train all
├─ D2      ───►  ├─ (All Data!)        data
├─ D3            │                  ├─ Global
│                │                  │  Model
│ PRIVACY RISK   │ BOTTLENECK       │
└─────────────────┴─────────────────┘

Problems:
  • Privacy: All data shared with server
  • Centralization: Single point of failure
  • Bandwidth: All raw data transmitted
  • Compliance: May violate regulations


╔═══════════════════════════════════════════════════════════════╗
║                   FEDERATED LEARNING                          ║
╚═══════════════════════════════════════════════════════════════╝

Data                Client              Server
├─ D1   (private)   ├─ Train local   ├─ Weights only
├─ D2   (private)   ├─ Extract w1    ├─ Average
├─ D3   (private)   ├─ Send w1 ───► ├─ New model
│                   │                │
│ STAYS LOCAL       │ NEVER SHARE    │
└────────────────────┴────────────────┴─────────────────┐
                                                        │
                                                 Global Model
                                                 (trained on
                                                  combined D1+D2+D3
                                                  without seeing
                                                  raw data!)

Benefits:
  • Privacy: Raw data never shared
  • Decentralized: No central server needed
  • Bandwidth: Only weights transmitted (small)
  • Compliance: Data stays on-device/on-premise
```

                                             Weights wait for all 3   │

## Error Scenarios

```
╔════════════════════════════════════════════════════════════╗
║              ERROR HANDLING IN AGGREGATION                ║
╚════════════════════════════════════════════════════════════╝

Scenario: Client missing

  SERVER WAITING:
  ├─ client_1 ✓ (weights received)
  ├─ client_2 ✓ (weights received)
  ├─ client_3 ✗ (NO RESPONSE)
  
  POST /aggregate
  {
    "client_ids": ["client_1", "client_2", "client_3"],
    "method": "average"
  }
  
  RESPONSE (400 Error):
  {
    "success": false,
    "error": "Missing updates from: client_3",
    "received": 2,
    "expected": 3
  }
  
  ACTION: Wait for client_3 or skip it

Scenario: Only 2 clients aggregate

  POST /aggregate
  {
    "client_ids": ["client_1", "client_2"],
    "method": "average"
  }
  
  RESPONSE (200 Success):
  {
    "success": true,
    "message": "Aggregated 2 updates",
    "round": 2
  }
  
  RESULT: Works! (fewer clients = noisier, but ok)
```

## Bandwidth Usage Comparison

```
╔════════════════════════════════════════════════════╗
║           BANDWIDTH REQUIREMENTS                   ║
╚════════════════════════════════════════════════════╝

Scenario: 3 Clients, 100 features, 100K samples each

CENTRALIZED LEARNING:
└─ Send all data to server
   ├─ 3 clients × 100K samples × 100 features × 8 bytes
   ├─ = 3 × 80MB
   └─ = 240MB per round (HUGE!)

FEDERATED LEARNING:
└─ Send only model weights
   ├─ 3 clients × (100 weights + 1 bias) × 8 bytes
   ├─ = 3 × 808 bytes
   ├─ = 2.4 KB per round
   └─ = 97.5MB SAVED per round!

SAVINGS: 97.5 MB / 240 MB = 99.9% reduction!
```

This demonstrates why federated learning is critical for privacy and efficiency.
